# Four Key Shell

可换皮肤的 4K 音游基础壳，使用 Godot 4 + GDScript。目标是“一套底层、多个定制成品”：谱面解析、音频时钟、判定、长键、暂停/重试、改键、延迟校准和结算都在壳层，UI 通过 `skins/active_skin.tscn` 接口接入。

示例皮肤已经按完整产品流程分层：首页、曲库/选曲、游戏 HUD、结算、成就/成绩和设置页。后续定制时可以只替换皮肤场景与主题，不改底层判定。

当前支持：

- 导入单独的 `.osu` 文件或 `.osz` 谱面包
- 从同目录读取 `AudioFilename` 指向的 mp3/ogg/wav
- 仅接受 osu!mania 4K（`Mode=3`、`CircleSize=4`）
- 普通音符和长按显示
- 长键按 osu!mania lazer 规则分开判定头部、身体断连和尾部：漏头仍保留灰色本体/尾部；身体断连不额外计入准确率，但会断连并把尾部最高封顶为 Meh；中途重按不能撤销此前失误
- 默认 `D F J K` 操作
- 示例皮肤可直接点击四个轨道按钮改键，改键会保存
- 主界面提供独立“设置”面板，集中管理改键、恢复默认键位和全屏
- 暂停、重试、按谱面 OverallDifficulty 计算的 Perfect/Great/Good/OK/Meh/Miss 判定；分数采用 0–1,000,000 的归一化 mania 风格计分，结算段位按严格边界计算
- 长键头/体/尾状态、提前松键恢复、尾部判定和血量条；设置中可切换练习模式（NoFail）
- 拖拽 `.osu/.osz` 到窗口，或点击“打开谱面”
- `.osz` 内含多个 4K 难度时提供难度选择
- 播放进度、结算统计、长键状态和谱面事件均通过公开信号提供
- `user://four_key_shell.cfg` 保存改键、全局时序偏移和音量
- `Esc` 暂停/继续，`R` 重开当前谱面，`F11` 切换全屏
- 下落速度可调为 50%–200%，适合不同熟练度和屏幕尺寸
- 自动保存最近打开的谱面，可从“最近谱面”直接恢复
- 启动时扫描内置 `Songs/` 和用户曲库；“导入到曲库”会复制 `.osu/.osz` 及所需音频
- 发布时将已授权内容放入 `BundledSongs/`，它会随客户包内置；开发测试用的 `Songs/` 不会被打包
- 练习按钮可前后跳转 10 秒，跳过部分不会被算作 Miss
- 演奏中显示本次击打早/晚毫秒反馈和最近击打误差条；结算提供简单评价（SS/S/A/B/C/D）和早晚击统计
- 每张谱面保存本地最佳成绩，暂停时提供继续、重试、设置菜单
- 练习区间可设起点/终点并循环播放，适合反复测试生成谱面的局部段落
- 按住未断连的长键身体会缓慢恢复血量；设置中提供自动演示，自动演示复用正常判定但不计入最佳成绩
- 内置轻量判定音效，可在设置中关闭，不需要额外资源文件
- 读取 `.osu` 的 hitsound 样本信息；谱面附带可播放的自定义样本时优先使用，否则按 Normal/Soft/Drum 与 Whistle/Finish/Clap 提供区分明显的本地 fallback 音效
- 导入谱面时检查同轨道长键重叠、同刻重复音符和空谱面，并在曲库/状态栏提示
- 设置中提供本地自动延迟校准，曲库提供按名称/路径搜索过滤
- 曲库提供完整试听：可暂停/继续、拖动进度、停止，并支持单曲循环、列表播放和列表循环；完成一局后自动保存本地回放，可回看且不计入最佳成绩
- 示例皮肤提供侧边导航和独立的首页、曲库、成就/成绩、设置、游戏与结算页面

## 运行

开发运行：安装 Godot 4 后，导入本目录的 `project.godot` 并运行。

构建客户版：双击 `构建发布版.bat`。输出在 `dist/FourKeyShell/`，客户只需双击其中的 `FourKeyShell.exe`，不需要安装 Godot。

构建测试版：双击 `构建测试版.bat`。它会生成 `dist/FourKeyShell-test-v*.zip`，测试版设置页提供“检查测试版更新”。更新器直接从公开 GitHub Release 检查和下载新版本，不需要安装 GitHub CLI 或登录 GitHub；更新时会在关闭程序后覆盖安装并重新启动。

公开仓库启用了 GitHub Actions：每次推送到 `main` 或提交 Pull Request 时，会自动运行 `tests/*_smoke.gd` 并构建 Windows 测试包，结果可在 Actions 的 Artifacts 下载。发布新测试版时，先把 `project.godot` 的版本改为目标版本，再推送匹配的 `v<版本>` 标签（例如 `v0.2.0-beta.8`），工作流会自动创建预发布 Release 并上传 zip。

换 UI：参照 `SHELL_API.md` 和 `SKIN_TEMPLATE.md` 替换 `skins/active_skin.tscn`，不要修改 `main.gd` 的判定逻辑。之后再次运行构建脚本即可得到新的定制 EXE。
